# Expression Reference

按写作场景选读中英文作品，帮助 AI 写作保留作者立场、组织具体材料，减少套话和机械表达。

当前版本：`0.5.1-preview.2`。这是供支持 `SKILL.md` 的 AI agent 使用的写作 Skill，包含构思与改稿指令、六种常用场景和十二个学科的参考文件。

## 设计理念：先处理写作中的选择

一段稿子可以语法正确，却让读者读完仍不知道具体说了什么：形容词很满，材料很少；每段都像结论，段落之间没有推进；加上第一人称后，又出现作者从未提供的经历。

Expression Reference 从读者、用途、材料和作者立场入手。它要求 agent 先判断这份稿子需要完成什么，再借相关作品中的写作选择组织正文。去掉套话只是其中一项工作；有时需要删除重复，有时需要补足推理，有时需要把限制条件移到相关结论旁边。

### 从真实作品中学习材料与顺序

参考文件收录中英文作品的链接、阅读范围、局部分析和原创练习。科技介绍可以观察怎样把功能接到使用任务；工作沟通可以观察怎样交代已经决定的事项；学科说明则需要保留定义、前提和结论之间的关系。

借鉴具体落在“这段先交代什么”“这个例子改变了哪个判断”“条件放在哪里才容易理解”上。原作者的经历、产品性能和机构承诺不能移到新稿中。作品作者的名气也不能替当前稿件证明效果。

### 按当前任务选读，控制加载范围

入口先区分文稿用途。六种场景覆盖口播、科技介绍、品牌文案、ToB 方案、工作沟通和技术解释；十二个学科文件处理不同领域的表达要求。已知对应文件时直接打开，只有用途不清时才用索引定位。

带短稿入口的文件可先读前 16 行；需要原作分析或复杂论证时，再读同一文件的相关部分。只有第二份参考会改变当前写法或主张时才增加读取。这让日常邮件保持简洁，也为复杂稿件留下展开空间。该机制限制默认读取范围，实际 token 用量仍受 agent 的读取方式与任务长度影响。

### 保留作者的声音，允许不同写法成立

同一组材料可以写成用途说明，也可以围绕读者的选择展开。Skill 允许根据用途改变中心、句长、节奏和解释深度。有作者亲自认可的样本时，样本可以帮助判断语气和表达距离。

它不要求固定删掉多少字，不按第一人称数量判断自然程度，也不把所有稿件写成某位名人的口吻。教学中的必要回扣、论文中的精确术语、文学中的留白，都可以有自己的作用。短与长都需要服务当前内容。

### 改表达时，保留每项主张的含义

具体化容易引入原文没有的内容。Skill 要求核对定义、数字、单位、研究对象、时间、条件、引用和承诺，尤其留意修改后的动词是否扩大了主张。

“计划支持”要保留计划状态，“部分用户”不能改成全部用户，“未报告”也不能直接推成无法计算。缺少事实时，询问会影响成稿的材料，或删去无法支持的判断。它不会为增加画面感而制造使用经历、心理活动或客户反馈。

### 中英文各自组织表达

中文稿按中文读者的阅读习惯组织关系；英文稿结合英文参考作品重新考虑重心和推进。需要 fusion 时，英文用于术语、真实界面名称、产品名或引语等具体功能。

这种安排为不同语言保留选择空间。是否同时交中英两版，由读者和媒介决定；中文版读起来顺，不能说明英文版也适合它的读者。

## 这些设计为什么有用

它的可取之处能落到编辑动作上，读者可以逐项检查当前稿件有没有改善。

| 写作时遇到的问题 | Skill 要求做的事 | 可以怎样检查结果 |
|---|---|---|
| 删掉常见 AI 用词后，文章依旧空泛 | 重新选择中心，让已有材料承担解释 | 读完能否说出具体功能、判断或下一步 |
| 所有内容都套同一种段落结构 | 按读者任务选择材料关系与次序 | 每段是否推进了当前问题 |
| 润色让承诺变大、条件变少 | 保留主张强度，把条件放回相关能力旁边 | 对照原稿的数值、对象、时态与限定 |
| 为“像人”添加作者没有的故事 | 只用已给材料，声音参考须获作者认可 | 第一人称经历和具体反馈能否找到原始材料 |
| 每次调用都读完整个参考库 | 先选场景或主学科，按需要扩大读取 | agent 是否只读了当前任务用得上的文件 |
| 改稿过程占满输出，成稿很少 | 默认交请求的正文及必要说明 | 用户能否直接拿到可继续使用的稿件 |

这些是设计带来的具体处理方式。目前的试用不足以证明它在所有模型、语言或写作任务中优于其他工具。实际使用时，可以保留原稿，比较改稿是否更容易理解，同时检查含义有没有改变。

## 一个例子：用已有事实替换空泛评价

以下是为介绍页新写的虚构示例，用于说明编辑选择，未作为模型评测结果。

**已给事实：** 一个工具当前可以导出 PDF，尚未提供 DOCX 导出。

**需要修改的稿子：**

> 这款工具凭借强大的导出能力，全面提升文档处理体验，让各种办公需求都能轻松解决。

**可采用的写法：**

> 当前可导出 PDF；如果你需要 DOCX 文件，还需另选处理方式。

修改删去了材料无法支持的“全面提升”和“各种办公需求”，保留了读者选择工具时需要知道的格式限制。它没有加入“我试过”“速度更快”或“用户都喜欢”。若读者需要了解具体导出步骤，后续应使用真实操作材料展开。

## 安装

需要 Git，以及支持本地 Skills 的 Codex 或 Claude Code。以下命令用于首次安装；目标目录已存在时，Git 会停止，请先检查已有版本。

### Codex

```sh
mkdir -p ~/.agents/skills
git clone https://github.com/prest4u/expression-reference.git ~/.agents/skills/expression-reference
```

重新打开会话后调用：

```text
$expression-reference 请修改下面这段科技介绍，面向第一次接触这个产品的读者，保留所有功能条件和数字：
[粘贴原文]
```

### Claude Code

```sh
mkdir -p ~/.claude/skills
git clone https://github.com/prest4u/expression-reference.git ~/.claude/skills/expression-reference
```

重新打开会话后调用：

```text
/expression-reference 请把这封工作邮件改得自然、直接，保留原有安排和承诺：
[粘贴原文]
```

其他支持 Skills 的 agent 可将本仓库放入其指定的技能目录，保持 `SKILL.md` 与 `references/` 的相对位置。

## 用法

可以要求写初稿、改已有稿件，或只指出具体问题。提供读者、用途、已有材料及需要保留的内容；有自己认可的声音样本时一并附上。

```text
用 expression-reference 写一段 60 秒的 AI 应用口播。
读者：第一次使用这类工具的人。
材料：[提供已确认的功能与使用条件]
语气：像向同事解释实际用途。
```

```text
用 expression-reference 修改这段论文说明。
请保留定义、研究对象、数值、单位和结论的强度，只调整表达与顺序。
[粘贴原文]
```

## 文件

- [SKILL.md](SKILL.md)：触发说明、文件选择、写作要求与交付方式。
- `references/`：口播、科技、品牌、ToB、工作沟通、技术解释，以及语言说明和诊断参考。
- [学科索引](references/disciplines/index.md)：定位十二个学科文件。
- [来源与历史试用记录](references/evidence.md)：原作阅读范围、研究限制及旧版试用说明。

本仓库包含 Markdown 文本，不带运行脚本、模型 API、遥测或密钥。Skill 指令与参考分析可直接在本地读取；打开引用网页或核对当前事实需要网络。模型调用由所用 agent 和账号决定。

## 版本与试用

保留现有 preview 版本，未因公开发布增加功能或重新评测。文件中的原创练习用于说明写作选择，历史试用不能证明不同模型或新任务都能稳定改善。没有做 AI 检测器通过率测试。

# 中英 fusion、翻译与本地化

## 中英 fusion 是一种真实的语体

在北美、香港、新加坡生活或在跨国团队工作的人，日常说话本来就是中英混着来的：“这个 PR 我 review 过了，有两个 comment 你看一下。”这不是不规范，是一个真实群体的自然语体。写给这群人、或者替这样的人写东西时，fusion 用对了，比“纯净”的中文更像人话。

用对的关键：英文词出现，是因为它在这里比中文更准、更顺、更是大家实际在说的，而不是为了显得国际化。

**通常留英文的：**

- 界面上实际显示的词：按钮、菜单、文件名、API 字段、命令。“点 Export，选 PDF。”
- 这个圈子里稳定在用、翻成中文反而认不出来的术语：prompt、token、PR、deadline、offer、OKR、onboarding。
- 中文没有完全对应、英文承载了特定意思的词：vibe、take、push back、ownership。
- 引用的原话、专有名词、作品名。

**通常说中文的：**

- 动词和句子骨架。fusion 的自然形态是中文语法、嵌入英文词：“我先 sync 一下”，而不是 “我 first sync 一下”。
- 普通概念。“我们 review 一下，然后 polish 一下整个 content”——除非这就是说话人真实的口头习惯，否则对大部分读者来说，“先看一遍，再改改措辞”更自然。

**判断谁在读：**

| 读者 | fusion 程度 |
|---|---|
| 说话人自己的社群、同事、熟悉这套语体的观众 | 跟着说话人的真实习惯走 |
| 中文为主的公众（国内短视频观众、家长、普通读者） | 只留界面词和必要术语；第一次出现的术语给一句中文说明 |
| 正式中文文书 | 尽量中文，专名和必须的术语除外 |
| 英文读者 | 写纯英文；中文专名按惯例拼音或给通行英译 |

**写法细节：**

- 英文词在中文句子里保持正常拼写和大小写（GitHub、iPhone、PR），中英文之间加空格（见 [chinese.md](chinese.md)）。
- 英文动词不加中文的时态变化，也不加英文的屈折变化：“我 review 过了”，不是“我 reviewed 了”。
- 同一个术语，一篇里固定一种说法。第一次可以写“检索（retrieval）”，后面挑一个用到底，不要每次都双语重复。
- 替用户写时，他们的 fusion 习惯就是他们声音的一部分，照着保留。他们说“deadline”就别改成“截止日期”，他们说“截止日期”也别改成“deadline”。

## 翻译：先理解意思，再用目标语言重新说

好的翻译不是逐词对应，是用目标语言的读者自然会用的方式，把同一个意思重新说一遍。

1. **读懂原文在做什么：** 告知、请求、说服、道歉、规定？同一句话的语用功能决定了译法。
2. **抓住不能变的东西：** 数字、专名、条件、否定、范围、时态、语气强度、承诺。
3. **用目标语言的语序和习惯重新组织。** 中文的长定语，英文常常拆成从句或分句；英文的被动、名词化，中文常常换成主动和动词。
4. **回头对照一遍** 上面那些不能变的东西。

**语气强度要对上。** 中文“可以”分别可能是能力（can）、许可（may）、建议（could），英文要按意思选。英文的 shall / will / may / should 在合同里各有法律含义，不能按一般文风随意替换。

**客套要按功能译，不按字面译。**

| 原文 | 字面 | 功能 |
|---|---|---|
| 辛苦了 | You've worked hard. | Thanks for pulling this together. |
| 麻烦你了 | Sorry to trouble you. | Thanks so much. / Really appreciate it. |
| 请多指教 | Please give me more guidance. | Looking forward to working with you. |
| 有空一起吃个饭 | Let's eat together when free. | （常是客气话，不一定真约；看语境） |
| I'd push back on that. | 我要推回那个。 | 这点我不太同意。 |
| Happy to help. | 很高兴帮助。 | 没问题。/ 随时找我。 |

**几个保意的例子：**

> 只有审核完成的申请，系统才会发通知。
> → The system sends notifications only for applications that have completed review.
> （“审核完成”不等于“审核通过”。原文如果指通过，要写 approved；不确定就问。）

> We plan to launch in June, subject to security review.
> → 我们计划六月上线，具体还要看安全审查的结果。
> （不能译成“安全审查后六月上线”，原文没有保证审查六月前完成。）

> The team hasn't tested the mobile version yet.
> → 团队还没测移动版。
> （不能补成“移动版暂时不能用”，没测和不能用是两回事。）

## 本地化和再创作（transcreation）

本地化可以动：称呼、礼貌方式、日期和单位格式、例子、文化指涉、句子顺序。不能悄悄动：产品的能力、价格、承诺、法律条款。

品牌文案、slogan、广告的跨语言版本常常需要再创作：在目标语言里找一个效果相同的说法，而不是意思最接近的说法。做法是先抓住原文的**核心信息**和**感觉**，再在目标语言里重新写，写出两三个方向让用户挑。再创作不能把含蓄的说法升级成绝对的保证。

## 双语版本的核对

- 两个版本说的是同一个对象、同样的数字、同样的时间、同样的承诺吗？
- 中文的“部分用户”在英文里变成了 users 吗？英文的 reported 在中文里消失了吗？
- 两种语言的句数、段数不必相同，每个版本都应该读起来像用该语言写的原文。
- 双语界面还要在真实界面上看截断和换行；只看文字确认不了。

## 引用和译文

- 引原文和自己的译文要分开标明。自己译的写“笔者译”或按文档规范标注，不冒充已出版的译本。
- 不确定官方译名时，用原名，或者注明是自译。

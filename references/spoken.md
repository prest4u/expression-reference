# R-SPOKEN｜AI 应用视频口播

用于介绍/教学/改稿，先判断观众是想做一次操作、理解机制，还是解决误解；路线是选项，非模板。以下分析为本项目判断，不冒称作者动机。

## 具体作品与表达选择

**O4｜Jeff Su，[Learn 80% of NotebookLM in Under 13 Minutes!](https://www.youtube.com/watch?v=EOmgC3-hznM)，2024-12-10，英文屏幕演示。** 已读站内自动字幕 0:00–12:27，细读 1:59–2:27、8:09–9:36 等；只静音抽看 2:20，未听全片。原文短摘：“all selected sources”。先提问，再解释全部勾选资料会参与，再给排除方法；会议记录/计划接简报/时间线/FAQ，输入与输出服务用途。可迁移：动作后回扣新增后果，旁白解释界面不能自明的理由。开场优越性、隐私因果、历史容量未核，不带入新稿；自动字幕非作者校对稿。

**O5｜漢克蔡 / Ainthology，[NotebookLM 学习演示](https://www.youtube.com/watch?v=TK9q8IjkO8s)，2025-10-19，繁中。** 已读 0:00–10:52 字幕（authored or unspecified），细读 1:50–4:45、6:22–7:04；只静音抽看 2:20。短摘：“這對我而言在吸收上是比較好的”（6:43）。先脉络/概念/细节再工具，100 字不够改 500 字；用途决定顺序和长度。标题完全掌握、来源多推出准确、致富承诺失效；仅混合案例，不当整片正向声音。UI 英文用于定位，中文说明目的。

**O2｜Grant Sanderson / Justin Sun，[Large Language Models explained briefly](https://www.3blue1brown.com/lessons/mini-llm/)，2024-11-20。** 已读完整官方英文文字改编，非逐字口播。明示假想脚本缺词，再展开预测/训练/结构；问题给机制解释去处。不要复制电影设定或强迫所有应用稿讲故事。

**O3｜Simon Willison，[Here’s how I use LLMs to help me write code](https://simonwillison.net/2025/Mar/11/using-llms-for-code/)，2025-03-11，英文实践文章。** 已读正文，重点预期落差、context/testing、colophon 与人接手。作者的完整推进从“为何有些开发者失望”到工作方式和失败处理，不只排列收益。可借预期、材料与接手的关系；这是文字实践，非口播，作者经历/当时工具结论不可借作用户实测。

## 写作取舍

操作入口适合已有使用意愿：选择→动作→结果/核对，省按钮复述，留选择理由。问题入口适合材料已有冲突：冲突→条件/机制→行动；没有冲突可直接回答。观众不知道用途、画面未显示、解释拖长或悬念虚构时换入口。结尾需要回扣才回扣，可给新后果，不必喊口号。

K1 支持先定取材/收束、再删或展开；K2 §9/13 支持解释与有功能的重述；N1 的语境性重复反驳“一律去重”。具体句序/停顿/距离是编辑选择。[原作版本与限度](evidence.md#k1)。P1 只提示情境可想象性，P2 仅摘要弱提示，P3 提醒画面/字幕/旁白时序；不能证明吸引力或禁字幕。[论文](evidence.md#p1)。

### 中文开发练习：同事实，两种中心

声明的 brief，非当前工具实测/用户经历：Sources 有旧/新说明，旧版仅 PDF，新版加 DOCX；回答用选中来源，取消旧版可排除它；有来源链接，仍须核原文。观众会勾选但不懂版本影响。

**操作：** 先看 Sources 里的两份说明。旧版只有 PDF，新版加了 DOCX。这次问新版，就先取消旧版的勾选。拿到答复，再沿着来源链接核对。资料选对了，和答案答对了，是两件事。

**问题：** 要导出 DOCX，为什么资料里又写着“只支持 PDF”？先别改提问。旧版和新版说明都在列表里，而工具会参考你勾选的资料。把旧版取消，只留新版，再沿回答的来源链接回到原文。先理清版本，再核对答案。

前者利于边做；后者解释材料冲突，耗更多理解时间。“先别改提问”只适用于此题，不排除普遍 prompt 问题。两稿均没保证正确；O4/O2 影响动作或问题入口，K2 影响收尾，措辞原创。

### English：从英文任务组织，而非译中文

O4 让 imperatives 指向屏幕动作，后句解释后果；O3 先校预期，再用可检查过程承接判断。想操作时以动词起手；想判断价值时可先呈现受材料支持的落差。长句可解释条件，短句可转移注意，不规定平均长度。You 不自动等于亲密，I 只用于有授权的真实说话者经历。

独立英文开发 brief：coding assistant can draft a change; a developer reviews it and runs relevant tests before use; if it stalls, the developer edits manually。没有测速度或成功率，不是测试题。

> Start with a change you can inspect. Let the assistant draft it, review the changes, and run the relevant tests before you use them. If it gets stuck, edit the code yourself. A draft gives you something to work on; it still needs your judgment.

O3 影响草稿/检查/接手关系，句序与收尾为原创判断。不是六条中文稿的翻译，不借作者个人经历，也不称英文性能已证。

## 针对口播的诊断与未知

[R-DIAG](diagnostics.md)：D2 回扣可必要；D4 长教学可导航/总结；D6 来源封闭不等于准确；D7 UI 名有定位功能；D8 个体体验不变观众保证。定位到句或画面。UI 用真实名字，不为 fusion 保留英文。

失败记录：旧流程稿合法但没交代选资料的理由；曾偷加生成按钮已删。所有开发练习非三条件实跑/holdout。书面停顿建议不等于实际朗读/测秒；未核视听时序。中文稳健正向整片与用户声音仍缺。

## 长讲解与短操作怎样选材料

**新增中文样本｜孙凝晖《人工智能与智能计算的发展》**，[中国科学院学部刊载讲稿](https://scicn.casad.cas.cn/wz/202407/t20240703_5024127.html)，刊载日 2024-07-03。选读讲稿开头、计算技术分期和大模型技术讨论，未听现场或核全部专业主张。长讲座先交代概念之间的关系，再展开变化；可借分类帮助陌生听众定位。政策性开场、宏观倡议和长历史段不适合直接移进一分钟工具演示。

英文 O3 这次重读开头与使用条件的说明。文章先回应使用落差，再接作者的做法；用于“为什么我的结果不同”的解释时，可保留预期调整。只想完成一次操作的观众，可从动作开始，不必先听一篇工具评价。中文讲稿和英文实践文章均是文字样本，不能推定实际口播的停顿、时长或吸引力。

| 观众此刻的任务 | 正文优先给什么 | 当前常见 Slop |
|---|---|---|
| 跟做一项操作 | 输入、动作、可辨认结果；画面已讲清的部分可省 | 每个按钮重复解释，却没说为什么选它 |
| 判断是否适合自己 | 一个已有任务、相关能力和条件 | 泛泛说提高效率，未说明省去什么工作 |
| 理解失误或原理 | 具体问题及推进它的关系 | 连续用“智能”代替机制，或假设全体观众都困惑 |
| 听较长讲解 | 必要概念与阶段关系，按实际内容导航 | 每小节都重说愿景或强行制造悬念 |

原创中文补充材料：工具生成了一份草稿，用户还没核内容。可写：“草稿已经生成。先看它有没有漏掉这次需要的信息，再核涉及的数字和来源。”不能改成已经完成任务或自动保证准确。

Independent English spoken fixture: a screen shows a draft and a source link; the link has not been checked.

> The draft is ready. Use the source link to check the claim you plan to keep.

有真实画面时把 link 对准可见位置；尚无界面材料时，这只是虚构练习，不能当录制说明。去掉“让工作从此轻松”后，旁白仍需要明确观众下一步。

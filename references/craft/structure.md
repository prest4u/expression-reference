# 结构：找到中心，选一个形状

## 先找到那句话

结构问题十有八九是想法问题。动笔前试三件事：

- **一句话测试：** 能不能用一两句话说出这篇的核心？
- **“所以呢？”测试：** 说完那句话，再问一句“所以呢”，你能回答吗？答案常常才是真正的中心。
- **复述测试：** 读者读完，能把你的主要意思转述给别人吗？

写不出那句话时，先放开写一稿。Anne Lamott 在 *Bird by Bird* 里管这叫 shitty first draft：初稿的任务是让你发现自己想说什么，不是给人看。写完回头找那句话，它常常埋在第三段，或者就是结尾，再从它出发重新组织。

一篇只有一个中心。别的好东西如果不服务它，留到下一篇。

## 按读者的需要选形状

没有万能结构。先看读者拿到这篇东西时要干什么。

| 形状 | 适合 | 骨架 | 风险 |
|---|---|---|---|
| 结论先行（Barbara Minto 的金字塔原理） | 读者要做决定、时间少：汇报、备忘录、邮件 | 结论 → 两到四个理由 → 每个理由的证据 | 对方有抵触时会像在推销；可以先摆出双方都认的问题 |
| SCQA | 读者还没意识到问题 | 情境（大家都知道的）→ 冲突（变了什么）→ 问题 → 答案 | 情境写得太长，答案出来时读者已经走了 |
| 问题 → 原因 → 办法 | 排障、提案、事故复盘 | 症状 → 为什么 → 怎么修、怎么防 | 原因是猜的却写成定论 |
| 时间或步骤 | 操作说明、事件经过 | 按发生顺序 | 每一步都一样重，读者抓不到关键 |
| 故事弧 | 人物、案例、品牌故事、演讲 | 处境 → 想要什么 → 阻碍 → 选择 → 变化 | 硬造冲突；真实材料里没有转折时别编 |
| 由浅入深 | 解释、教学、科普 | 最简单的正确版本 → 一层层加条件和例外 | 第一层简单过头，变成错的 |
| 比较 | 选型、评测 | 按维度逐项比，或逐个对象讲完再总结 | 维度不一致，A 说价格、B 说体验 |
| 倒金字塔 | 新闻、通知、更新 | 最重要的事实 → 次要 → 背景 | 只适合可以从尾部截断的文字 |
| 探索 | 随笔、思考类文章 | 一个问题 → 尝试 → 推翻 → 新的理解 | 绕了一圈没到任何地方 |
| 清单 | 真正并列、互相独立、读者会挑着看 | 条目 | 把有因果的推理也拆成了条 |

长篇纪实或复杂报告，值得在动笔前花时间排结构。John McPhee 在 *Draft No. 4* 里写，他会先把所有材料分类摆开，找到一个能让材料自然流动的形状，再开始写。短稿不必这样，但道理一样：先决定顺序，再写句子。

## 开头

从读者的兴趣开始，而不是从你思考的起点开始。

好开头的几种入口：

- **直接给结论或消息。** 适合工作文字。“下周的上线要推迟。”
- **读者心里真有的那个问题。** “为什么同样的提示词，昨天能用，今天就不行了？”
- **一个具体的场景或人。** 适合特稿、演讲、品牌故事。
- **一个让人停下来的事实。** 前提是它真实，而且和后文有关。
- **一个张力或矛盾。** “我们的用户越来越多，收入却在下降。”

要删的开头：清嗓子（“随着……的发展”），复述题目，从字典定义说起，“在开始之前，我想先说明……”。

一个实用的办法：写完后删掉第一段，看看是不是更好了。常常是。

长篇特稿常用一个场景开头，紧接着用一段话告诉读者“这个故事为什么重要、它在讲什么”——美国新闻业管这一段叫 nut graf。场景负责把人拉进来，nut graf 负责告诉他们为什么留下。缺了后者，读者会觉得在看一段与己无关的故事。

> 弱：随着远程办公的普及，会议效率问题日益受到关注。本文将从多个角度探讨如何提升会议效率。
>
> 强：上个季度，我们团队平均每人每周开 11 小时会。我把其中一周的会议记录翻了一遍，发现一半的会结束时没人知道下一步谁来做。

（第二个开头的数字和经历必须真实存在；没有的话，换成你真有的那个观察。）

## 中间：比例和推进

- **篇幅给读者觉得难的地方，** 不给你觉得好写的地方。
- **每一节都要推进：** 新信息、新角度、新问题。如果两节对调顺序也不影响理解，结构可能只是罗列。
- **转场靠内容，不靠路标。** “但这个办法有一个前提……”比“接下来我们看第二点”有力。
- **长文做反向提纲（reverse outline）：** 把写好的每段压成一句话，列出来。缺什么、哪里重复、顺序哪不对，一眼就看出来。

## 结尾

说完就停。好的结尾有几种：

- **一个含义：** 前面的事实加起来，意味着什么。
- **下一步：** 读者现在可以做什么，或者你需要他们做什么。
- **回到开头的意象，** 但带着读完全文后的新意义。
- **一个由全文挣来的开放问题。** 不能是“未来会怎样，让我们拭目以待”。

要避免：复述全文；上价值（“这不仅是一次技术升级，更是一场思维革命”）；空洞号召（“让我们携手共创未来”）；不需要时硬加的行动号召。

> 弱：总之，会议效率的提升需要我们每个人的共同努力，让我们从今天开始，让每一次会议都更有价值。
>
> 强：下周开始，每个会最后五分钟只做一件事：念出每个待办和它的负责人。念不出名字的，就不算决定。

## 标题和小标题

- 标题说出内容，或者提出一个真问题。不做标题党：标题许诺的，正文要兑现。
- 报告和文档里，信息型小标题（说出这一节的结论，如“迁移成本主要在数据清洗”）比标签型（“背景”“分析”“总结”）有用得多。只扫小标题的读者也能拿到主线。
- 几百字的短文不需要小标题。

## 列表还是段落

- **列表：** 项目并列、互相独立、读者会扫读或挑着用（步骤、清单、规格、选项）。
- **段落：** 有因果、有推理、有转折。把推理拆成 bullets，会把“因为”“所以”“但是”一起拆掉。
- Amazon 的六页 narrative memo 用完整段落代替幻灯片里的要点，理由正是这个。Jeff Bezos 在 2004 年一封常被引用的内部邮件里说，叙事结构逼人想清楚什么比什么重要、事情之间怎样关联，要点列表却可以把这些略过去（邮件经 Brad Stone 的 *The Everything Store* 等转述流传）。他在 2017 年致股东信里补充：好的备忘录要写了再写。
